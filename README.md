# Проверка сокращений в инженерных документах

Программа проверяет текстовые и markdown-файлы на соответствие сокращений
правилам ГОСТ 2.316 и ГОСТ 21.101. Результат — JSON-отчёт со списком ошибок
и корректных сокращений двумя алгоритмам: детерминированным и с использованием языковой модели.

---

## Структура проект

det.py - Детерминированная проверка сокращений 

llm_testing.py - Проверка через языковую модель

rules.yaml - Словарь сокращений: полное написание и допустимые варианты

example.txt - Пример входного файла для проверки

extra_allowed.txt - Список дополнительных верных сокращений (для llm_testing.py)

examples_of_result - Папка с примерами результатов работы детерминированного алгоритма, моделей google/gemma-2-2b-it, deepseek-ai/DeepSeek-V3-0324
и Qwen/Qwen3-Coder-30B-A3B-Instruct

README.md - Документация

---

## Алгоритм работы

**Детерминированный алгоритм** (`det.py`) находит кандидатов на сокращение
тремя регулярными выражениями: слова с точкой, аббревиатуры (2–3 буквы), 
короткие слова. Каждый кандидат проверяется по словарю `rules.yaml`:
сначала точное совпадение, затем составные сокращения через дефис и пробел,
затем: по префиксу без точек, потом расстоянием Левенштейна с порогом 2.

**LLM** (`llm_testing.py`) получает содержимое rules.yaml(только allowed) и extra_allowed.txt 
, делит текст на фрагменты по 1500 символов с перекрытием 100 символов. Формируется промпт и 
отправляется через InferenceClient (Hugging Face API) напрямую. Из ответа модели извлекается JSON-массив.

- Python 3.8+

## Установка и запуск

### Windows

**Установка зависимости:**
```cmd
pip install pyyaml huggingface_hub
```

**Запуск det.py, вывод в терминал:**
```cmd
python det.py -i example.txt -r rules.yaml
```

**Запуск llm_testing, вывод в терминал:**
```cmd
set HF_TOKEN=hf_ваш_токен
python llm_testing.py -i example.txt -r rules.yaml -e extra_allowed.txt -o result_llm.json
```

**Запуск det.py, с сохранением отчёта:**
```cmd
python det.py -i example.txt -r rules.yaml -o result_det.json
```

---

### macOS/Linux

**Установка зависимости:**
```bash
pip3 install pyyaml huggingface_hub
```

**Запуск det.py, вывод в терминал:**


**Запуск llm_testing, вывод в терминал:**

```bash
export HF_TOKEN=hf_ваш_токен
```

## Входные файлы

**`example.txt`** — проверяемый текст.
Hазметка (заголовки, ссылки, таблицы) удаляется перед анализом,
позиции символов при этом сохраняются.

**`rules.yaml`** — словарь сокращений. Каждая запись содержит полное написание
и список допустимых сокращений:

```yaml
- full: "Разработал"
  allowed: ["разраб."]

- full: "Документ"
  allowed: ["докум.", "док."]
```
** extra_allowed.txt ** - cписок дополнительных верных сокращений (для llm_testing.py)

# Ограничения программы det.py

## 1. Требует полного словаря

Все допустимые сокращения должны быть заранее внесены в `rules.yaml`.

## 2. Одиночные инициалы всегда пропускаются

Любая одиночная буква с точкой (`Н.`, `А.`, `П.`) считается инициалом
и пропускается без проверки. Из-за этого в таких сокращениях как `Н. контр.` 
или `Т. контр.` будет рассмотрено только `контр.`.

## 3. Аббревиатуры длиннее трёх букв не ищутся

Регулярное выражение для аббревиатур ограничено двумя-тремя заглавными
буквами (поскольку отсутствуют в ГОСТ).

## 4. Слова без точки не проверяются по словарю

Если сокращение написано без завершающей точки (`Разраб` вместо `Разраб.`,
`Гл инж` вместо `Гл. инж.`), программа не распознает его как сокращение
и вернёт ПРОПУСК. Пропущенная точка внутри составного сокращения также
не обрабатывается.

## 5. Ложное распознавание слов с точкой

Если в тексте встречается слово, оканчивающееся точкой (конец предложения) 
и не являющееся сокращением (например, «конь.»), программа может классифицировать 
его как потенциальное сокращение.
